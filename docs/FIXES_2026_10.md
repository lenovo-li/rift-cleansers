# 2026年10月修复与改进（含联机反馈改进）

## 修复的Bug

### 1. 游戏提前结束bug（关键bug）✅
**问题**：玩家在游戏进行到1分钟左右时被敌人一击秒杀（伤害2516），远超正常值。

**原因**：
- `gameplay/spawn/enemy_spawner.gd:87` 直接修改了共享的预加载资源 `def.attack_damage`
- 每次生成敌人都会累乘缩放倍率（`power = 1 + t/60 × 0.08`）
- 随着游戏时间推移和生成次数增加，伤害指数增长
- 例如：基础伤害6，前64秒生成约200次后累积到 6 → 2516（约420倍）

**修复**：
- 在 `spawn_enemy()` 中使用 `def.duplicate()` 创建独立副本
- 只修改副本的属性，不影响原始共享资源
- 修复后敌人伤害按时间正常递增，不会累积

**验证**：
- 修复前：60秒时玩家死亡（hp=0）
- 修复后：60秒时玩家存活（hp=940）

**文件**：`gameplay/spawn/enemy_spawner.gd`

## 新功能

### 2. 升级系统改为10选1 ✅
**改进**：
- 从5选1改为10选1，提供更多选择
- 上下两排布局（每排5张卡片）
- 卡片尺寸：280×320像素

**技能卡分配策略**：
- **上排（技能区）**：3张旧技能升级 + 2张新技能/替换
- **下排（其他区）**：被动、属性加成、装备强化
- 某类不够时互相补位，保证选项多样性

**键盘操作**：
- 按键 1-9 选择前9张卡
- 按键 0 选择第10张卡
- 按键 R 刷新选项

**手柄操作**：
- 十字键上下左右移动焦点（支持跨排导航）
- A键确认选择
- Y键刷新选项

**文件**：
- `gameplay/progression/upgrade_system.gd`
- `ui/upgrade_panel.gd`
- `ui/upgrade_card.gd`

### 3. 升级可刷新2次 ✅
**改进**：
- 每次升级可刷新选项2次（原来只能刷新1次）
- 标题显示剩余刷新次数："(还可刷新 2 次)"
- 刷新次数用尽后按钮自动禁用

**网络同步**：
- 主机追踪每个客户端的刷新次数
- 客户端请求刷新时主机校验并扣除次数
- 防止作弊

**文件**：
- `gameplay/progression/upgrade_system.gd` (REFRESH_COUNT 常量)
- `ui/upgrade_panel.gd`
- `net/net_session.gd`
- `scenes/game_scene.gd`

---

### 4. 全局UI按钮点击音效 ✅
**改进**：
- 所有按钮（菜单、设置、暂停、升级面板等）自动播放点击音效
- 通过 `UiTheme.install()` 全局监听按钮添加，自动连接音效
- 避免每个面板都手动添加音效代码

**实现细节**：
- 使用 `SceneTree.node_added` 信号监听按钮创建
- 为每个按钮的 `pressed` 信号连接音效播放
- 使用元数据标记避免重复连接
- 已处理音效的按钮可设置 `no_auto_sound` 元数据跳过

**文件**：`ui/ui_theme.gd`

## 技术细节

### 卡片布局计算
```
屏幕：1920×1080
卡片：280×320
间距：15px

一排5张宽度：280×5 + 15×4 = 1460px
两排高度：320×2 + 15 = 655px

vbox区域：
- 宽度：-780 到 780 = 1560px ✓
- 高度：从中心-400开始，足够容纳 ✓
```

### 敌人伤害缩放
```gdscript
// 正确做法：复制资源
var def_copy: EnemyDef = def.duplicate()
def_copy.attack_damage *= power  // 只修改副本

// 错误做法（bug）：
enemy.def.attack_damage *= power  // 修改共享资源！
```

### 刷新次数追踪
```gdscript
// 单人游戏
var _can_refresh: int = 2  // 本地计数

// 联机游戏
var _can_refresh: Dictionary = {}  // slot -> 剩余次数
_can_refresh[slot] = UpgradeSystem.REFRESH_COUNT
```
